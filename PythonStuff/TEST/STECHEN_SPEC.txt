STECHEN SYSTEM — FUNCTIONAL SPEC (MINIMAL + COMPLETE)
====================================================

This document defines all scripts, global rules, and the exact FIELD and METHOD
pipelines used by the STECHEN automation system.

No natural-language mapping rules are included —
only the operational, mechanical structure required by the engine.

OVERALL GOAL:
The end result of any STECHEN run is to produce a SINGLE FUNCTIONING JAVA CLASS
(e.g., a game, a utility, etc.) with all required fields and methods added via
the defined FIELD and METHOD pipelines.

At the very beginning of EVERY STECHEN workflow, it is COMPULSORY to:
    1) Create a new project folder
    2) Set that folder as the current working directory
    3) Download all required bytecode-manipulation libraries

That sequence is:

    java CreateDirectory --name <ProjectFolder>
    java CurrentDirUpdate --dirname <ProjectFolder>
    java DynamicJarLoader --library net.bytebuddy:byte-buddy:1.15.3
    java DynamicJarLoader --library org.ow2.asm:asm:9.8
    java DynamicJarLoader --library org.ow2.asm:asm-tree:9.8

Only AFTER these 3 steps may any field or method pipeline begin.


AVAILABLE SCRIPTS (FULL LIST)
-----------------------------

CreateDirectory
description: creates a directory with the given name
usage: java CreateDirectory --name <directoryName>

CurrentDirUpdate
description: sets the current working directory to be the specified folder
usage: java CurrentDirUpdate --dirname <directoryName>

CreateTextFile
description: creates a text file and optionally inserts content into it
usage: java CreateTextFile --name <fileName> [--path <targetPath>] [--content <textContent>]

GitFolderDownloader
description: rebases or updates the core driving scripts in a folder
usage: java GitFolderDownloader --name <folderName>

RunClass
description: executes a compiled Java class (calls main)
usage: java RunClass --class <ClassName>

ClassFieldAdder
description: adds a field definition to an existing .class file
usage: java ClassFieldAdder --classNameToModify <Name> --field fieldName:fieldType

DynamicClassCreator
description: creates a minimal base .class with default String name + sayHello()
usage: java DynamicClassCreator --name <className>

DynamicJarLoader
description: loads an external library by groupId:artifactId:version
usage: java DynamicJarLoader --library <groupId:artifactId:version>

ClassToSpecJsonFile
description: generates a spec JSON file listing all fields + methods of a class
usage: java ClassToSpecJsonFile --targetFile <YourClass.class>

SpecMethodLogicAppender
description: appends logic from a txt file into newMethodLogicSpec of a spec JSON
usage: java SpecMethodLogicAppender --specFile <SpecFile.json> --logicFile <MethodLogicFile.txt>

SpecFieldLogicAppender
description: appends NEW FIELD description into newFieldDescSpec
usage: java SpecFieldLogicAppender --specFile <SpecFile.json> --logicFile <FieldDescription.txt> --fieldName <FieldName>

OpenAiFieldDelegateGenerator
description: generates a field-only delegate class from a spec JSON
usage: java OpenAiFieldDelegateGenerator --Target_spec <SpecFile.json>

OpenAiMethodDelegateGenerator
description: generates a method-focused delegate class from a spec JSON
usage: java OpenAiMethodDelegateGenerator --Target_spec <SpecFile.json>

ClassMethodAdder
description: copies all methods from delegate into target class
usage: java ClassMethodAdder --classNameToModify <Name> --delegateclass <Delegate>

ClassMethodCloner
description: clones ONE method bytecode from delegate → target class
usage: java ClassMethodCloner --classNameToModify <Class> --delegateclass <Delegate> --method <methodName>

JarClassExtractor
description: extracts classes from jar files
usage: java JarClassExtractor --jar <jar1> [--jar <jar2> ...] [--target <outputDirectory>]

ClassFieldCloner
description: clones ONE public field from delegate → base class
usage: java -cp .;asm-9.8.jar;asm-tree-9.8.jar ClassFieldCloner --classNameToModify <BaseClass> --delegateclass <DelegateClass> --field <fieldName>


GLOBAL RULES
------------

Rule 0 — REQUIRED before any pipeline:
    net.bytebuddy:byte-buddy:1.15.3
    org.ow2.asm:asm:9.8
    org.ow2.asm:asm-tree:9.8

Rule 1 — All STECHEN operations run line-by-line.

Rule 2 — Every new project must begin with:
    CreateDirectory → CurrentDirUpdate → REQUIRED JAR DOWNLOADS

Rule 3 — Spec regeneration boundaries:
    ClassToSpecJsonFile rebuilds the spec from a .class file and DOES NOT know about
    newFieldDescSpec or newMethodLogicSpec.

    Allowed:
        • At the START of a field or method pipeline.
        • AFTER clone/add is complete AND BEFORE next pipeline.

    Forbidden:
        • Between SpecFieldLogicAppender and OpenAiFieldDelegateGenerator.
        • Between SpecMethodLogicAppender and OpenAiMethodDelegateGenerator.

Rule 4 — DynamicClassCreator always produces:
    • one String field "name"
    • one public method sayHello()

Rule 5 — Delegates must always be named:
    <ClassName>Delegate.java

Rule 6 — Only main() may be static.

Rule 7 — UNIFIED DELEGATE PATH:
    Spec → Delegate → Clone/Add → Base

Rule 8 — Field–Method dependency:
    A method may only be created after all fields it uses exist in the base class and spec.

Rule 9 — Method call dependency:
    If method A calls method B, then B must exist before A is inserted.

Rule 10 — Required libraries must exist before running:
    ClassFieldCloner, ClassMethodCloner, DynamicClassCreator

Rule 11 — Per-field and per-method execution:
    • ONE FIELD → run ONE full FIELD pipeline
    • ONE METHOD → run ONE full METHOD pipeline
    No batching of multiple fields or methods.


FIELD CREATION PIPELINE
-----------------------

Goal: Add ONE new field to the base class.

1) Generate or update the spec JSON
       java ClassToSpecJsonFile --targetFile <BaseClass>.class

2) Create a natural-language field description
       java CreateTextFile --name <FieldDesc>.txt --content "<description>"

3) Append this description into newFieldDescSpec
       java SpecFieldLogicAppender --specFile <Spec>.json --logicFile <FieldDesc>.txt --fieldName <FieldName>

4) Generate the field delegate
       java OpenAiFieldDelegateGenerator --Target_spec <Spec>.json

5) Transfer the field into the base class
       java ClassFieldCloner  (preferred)
       or java ClassFieldAdder

After step 5, you MAY refresh the spec:
       java ClassToSpecJsonFile --targetFile <BaseClass>.class


METHOD CREATION PIPELINE
------------------------

Goal: Add ONE new method to the base class.

1) Generate or update the spec JSON
       java ClassToSpecJsonFile --targetFile <BaseClass>.class

2) Create a natural-language method logic description
       java CreateTextFile --name <MethodDesc>.txt --content "<method logic>"

3) Append this logic into newMethodLogicSpec
       java SpecMethodLogicAppender --specFile <Spec>.json --logicFile <MethodDesc>.txt

4) Generate the method delegate
       java OpenAiMethodDelegateGenerator --Target_spec <Spec>.json

5) Transfer the method into the base class
       java ClassMethodCloner  (preferred)
       or java ClassMethodAdder

After step 5, you MAY refresh the spec:
       java ClassToSpecJsonFile --targetFile <BaseClass>.class


EXAMPLE FULL PIPELINE
---------------------

# 0. Project setup
java CreateDirectory --name MATRIX
java CurrentDirUpdate --dirname MATRIX

# Required jars
java DynamicJarLoader --library net.bytebuddy:byte-buddy:1.15.3
java DynamicJarLoader --library org.ow2.asm:asm:9.8
java DynamicJarLoader --library org.ow2.asm:asm-tree:9.8

# 1. Base class + initial spec
java DynamicClassCreator --name Base
java ClassToSpecJsonFile --targetFile Base.class

# 2. Method pipeline example
java CreateTextFile --name myMethod.txt --content "<method description>"
java SpecMethodLogicAppender --specFile Base_spec.json --logicFile myMethod.txt
java OpenAiMethodDelegateGenerator --Target_spec Base_spec.json
java ClassMethodCloner --classNameToModify Base --delegateclass BaseDelegate --method myMethod

# 3. Optional refresh
java ClassToSpecJsonFile --targetFile Base.class

# 4. Run the final class
java RunClass --class Base
