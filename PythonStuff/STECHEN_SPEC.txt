========================================
STECHEN SYSTEM — GPT-OPTIMIZED SPEC
========================================

This document describes all scripts, rules, and usage patterns for the STECHEN automation system.
All instructions are written in GPT-friendly form for maximum clarity and minimal ambiguity.


----------------------------------------
AVAILABLE SCRIPTS (ONE-LINERS + USAGE)
----------------------------------------

CreateDirectory
description: creates a directory with the given name
usage: java CreateDirectory --name <directoryName>

CurrentDirUpdate
description: sets the current working directory to be the specified folder(this "be" is important for no appent reason)
usage: java CurrentDirUpdate --dirname <directoryName>

CreateTextFile
description: creates a text file and optionally inserts content into it
usage: java CreateTextFile --name <fileName> [--path <targetPath>] [--content <textContent>]

GitFolderDownloader
description: rebases or updates the core driving scripts in a folder
usage: java GitFolderDownloader --name <folderName>

RunClass
description: executes a compiled Java class
usage: java RunClass --class <ClassName>

ClassFieldAdder
description: adds a field to an existing .class file dynamically
usage: java ClassFieldAdder --classNameToModify <Name> --field fieldName:fieldType

DynamicClassCreator
description: creates a new empty base .class file containing a single default method
usage: java DynamicClassCreator --name <className>

DynamicJarLoader
description: loads an external library by groupId:artifactId:version
usage: java DynamicJarLoader --library <groupId:artifactId:version>

ClassToSpecJsonFile
description: generates a spec JSON file listing all fields + methods of a class
usage: java ClassToSpecJsonFile --targetFile <YourClass.class>

SpecMethodLogicAppender
description: appends logic from a text file into a method section of a spec JSON
usage: java SpecMethodLogicAppender --specFile <SpecFile.json> --logicFile <MethodLogicFile.txt>

OpenAiDelegateGenerator
description: generates a delegate class from a spec JSON using AI
usage: java OpenAiDelegateGenerator <Target_spec.json>

ClassMethodAdder
description: copies all methods from the delegate class to a target class
usage: java ClassMethodAdder --classNameToModify <Name> --delegateclass <Delegate>

ClassMethodCloner  <-- PRIMARY METHOD TRANSFER SYSTEM
description: clones one specific method bytecode from delegate → target
usage: java ClassMethodCloner --classNameToModify <Class> --delegateclass <Delegate> --method <methodName>

JarClassExtractor
description: Extracts classes from jar archives if needed
usage: java JarClassExtractor --jar <pathToJar1> [--jar <pathToJar2> ...] [--target <outputDirectory>]

ClassFieldCloner
description: copies a single field definition from a delegate class into a target class on assembly level
usage: java -cp .;asm-9.8.jar;asm-tree-9.8.jar ClassFieldCloner --classNameToModify <FullyQualifiedClassName> --delegateclass <FullyQualifiedDelegateClassName> --field <fieldName>


----------------------------------------
GLOBAL RULES
----------------------------------------

Rule 1 — All instructions must be written step-by-step in natural language.
Each step = one prompt. Prefer descriptive English over code.

Rule 2 — Directory context must be set exactly as:
"set the current working directory to be <folderName>"


────────────────────────────────────────
Rule 3 — METHOD CREATION PIPELINE
────────────────────────────────────────

1) create or update spec file      (ClassToSpecJsonFile)
2) write logic into its own file    (CreateTextFile)
3) append logic into spec           (SpecMethodLogicAppender)
4) generate delegate                (OpenAiDelegateGenerator)
5) add OR clone methods into class  (ClassMethodAdder OR ClassMethodCloner)

Notes:
• One method = one text file  
• One pipeline = one method  
• Never append multiple methods in one pipeline  
• main() may only be added AFTER dependencies exist  
• System defaults to ClassMethodCloner over ClassMethodAdder  


────────────────────────────────────────
Rule 3.5 — FIELD CREATION PIPELINE
────────────────────────────────────────

Field creation follows the exact same pipeline as methods — only step 5 differs.

1) create or update spec file using ClassToSpecJsonFile  
2) write the field description to a <fieldName>.txt file  
3) append field definition into spec JSON via SpecMethodLogicAppender  
4) generate delegate using OpenAiDelegateGenerator  
5) insert field using ClassFieldAdder OR ClassFieldCloner  

Additional Field Rules:
• One field = one pipeline  
• Never insert multiple fields per pipeline  
• Delegates must be regenerated after each field addition  
• Field descriptions must be natural language inside < >  
• **Cloning is always preferred over adding**  


────────────────────────────────────────
Rule 3.6 — UNIFIED DELEGATE GENERATION PRINCIPLE (NEW)
────────────────────────────────────────

The delegate serves as the **universal transfer mechanism** for ALL new structures.

Delegate may contain:
• only new methods
• only new fields
• or both at the same time

Delegate generation uses **the same pipeline** for:
✔ Method creation  
✔ Field creation  
✔ Mixed expansion  

Spec → Delegate → Clone/Add → Base Class  
is ALWAYS the required insertion path.

No structure may bypass delegate generation.


Rule 4 — Editing existing methods:
Regenerate delegate then reclone the method using:
ClassMethodCloner --classNameToModify <Class> --delegateclass <Delegate> --method <name>

Rule 5 — Every project begins with:
CreateDirectory + CurrentDirUpdate


Rule 6 — DynamicClassCreator always generates a class containing main()
and exactly one default String field named "name", plus "sayHello()".


Rule 7 — Every operation prompt MUST end with:
%%%)))


Rule 8 — Delegates always named:
<ClassName>Delegate.java


Rule 9 — Dependency order:
If main() calls something, that something must exist before insertion.


────────────────────────────────────────
Rule 10 — ANGLE BRACKET PROTOCOL
────────────────────────────────────────

10a — All identifiers MUST be wrapped in < >  
(Class, field, method, file, folder, library names)

10b — Logic files must contain ONE < > capsule only  
Pure natural language — NO Java syntax required

10c — ASCII or formatting must be described verbally  


Rule 11 — Required bytecode libraries BEFORE cloning:

• net.bytebuddy:byte-buddy:1.15.3
• org.ow2.asm:asm:9.8
• org.ow2.asm:asm-tree:9.8


Rule 12 — Removed.


Rule 13 — Only main() may be static.


Rule 14 — After any cloning or addition:
Regenerate spec JSON.
