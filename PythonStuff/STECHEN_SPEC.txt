========================================
STECHEN SYSTEM — GPT-OPTIMIZED SPEC
========================================

This document describes all scripts, rules, and usage patterns for the STECHEN automation system.
All instructions are written in GPT-friendly form for maximum clarity and minimal ambiguity.


----------------------------------------
AVAILABLE SCRIPTS (ONE-LINERS + USAGE)
----------------------------------------

CreateDirectory
description: creates a directory with the given name
usage: java CreateDirectory --name <directoryName>

CurrentDirUpdate
description: sets the current working directory to be the specified folder(this "be" is important for no appent reason)
usage: java CurrentDirUpdate --dirname <directoryName>

CreateTextFile
description: creates a text file and optionally inserts content into it
usage: java CreateTextFile --name <fileName> [--path <targetPath>] [--content <textContent>]

GitFolderDownloader
description: rebases or updates the core driving scripts in a folder
usage: java GitFolderDownloader --name <folderName>

RunClass
description: executes a compiled Java class
usage: java RunClass --class <ClassName>

ClassFieldAdder
description: adds a field to an existing .class file dynamically
usage: java ClassFieldAdder --classNameToModify <Name> --field fieldName:fieldType

DynamicClassCreator
description: creates a new empty base .class file containing a single default method
usage: java DynamicClassCreator --name <className>

DynamicJarLoader
description: loads an external library by groupId:artifactId:version
usage: java DynamicJarLoader --library <groupId:artifactId:version>

ClassToSpecJsonFile
description: generates a spec JSON file listing all fields + methods of a class
usage: java ClassToSpecJsonFile --targetFile <YourClass.class>

SpecMethodLogicAppender
description: appends logic from a text file into a method section of a spec JSON
usage: java SpecMethodLogicAppender --specFile <SpecFile.json> --logicFile <MethodLogicFile.txt>

SpecFieldLogicAppender
description: appends a NEW FIELD description inside "newFieldDescSpec" section of a spec JSON
usage: java SpecFieldLogicAppender --specFile <SpecFile.json> --logicFile <FieldDescription.txt> --fieldName <nameOfField>

OpenAiFieldDelegateGenerator
description: generates a field-only delegate class from a spec JSON using AI (public fields for cloning)
usage: java OpenAiFieldDelegateGenerator <Target_spec.json>

OpenAiMethodDelegateGenerator
description: generates a method-focused delegate class from a spec JSON using AI (methods for cloning)
usage: java OpenAiMethodDelegateGenerator <Target_spec.json>

ClassMethodAdder
description: copies all methods from delegate into target class
usage: java ClassMethodAdder --classNameToModify <Name> --delegateclass <Delegate>

ClassMethodCloner   <-- PRIMARY METHOD TRANSFER
description: clones ONE method bytecode from delegate → target
usage: java ClassMethodCloner --classNameToModify <Class> --delegateclass <Delegate> --method <methodName>

JarClassExtractor
description: extracts classes from .jar files
usage: java JarClassExtractor --jar <jar1> [--jar <jar2> ...] [--target <outputDirectory>]

ClassFieldCloner   <-- PRIMARY FIELD TRANSFER
description: copies a single public field from delegate → base at bytecode level
usage: java -cp .;asm-9.8.jar;asm-tree-9.8.jar ClassFieldCloner --classNameToModify <BaseClass> --delegateclass <DelegateClass> --field <fieldName>


----------------------------------------
GLOBAL RULES
----------------------------------------

Rule 1 — All instructions must be written step-by-step in natural language.
One instruction = one line.

Rule 2 — Directory must always be set exactly as:
set the current working directory to be <folderName> %%%)))


────────────────────────────────────────
Rule 3 — METHOD CREATION PIPELINE
────────────────────────────────────────

1) create or update spec file              (ClassToSpecJsonFile)
2) write logic into a txt file             (CreateTextFile)
3) append method logic using               (SpecMethodLogicAppender)
4) generate method delegate                (OpenAiMethodDelegateGenerator)
5) insert method using                     (ClassMethodCloner preferred) or ClassMethodAdder

Notes:
• One method per file
• One file per pipeline
• No multiple method logic blocks at once
• main() may only be inserted if deps exist
• ClassMethodCloner is default insertion tool

HARD FIELD-ORDER CONSTRAINT (METHODS):
• Any method that reads or writes a field <F> MAY ONLY be created
  after <F> exists in the base class / spec.
• That means: run the full FIELD CREATION PIPELINE for every new field
  BEFORE running a METHOD CREATION PIPELINE that uses that field.
• newMethodLogicSpec MUST NOT describe logic that accesses fields
  which are not present in the latest spec JSON.


────────────────────────────────────────
Rule 3.5 — FIELD CREATION PIPELINE  (Corrected)
────────────────────────────────────────

Field creation mirrors method creation — only appender + delegate + step 5 change.

1) create or update spec JSON using         (ClassToSpecJsonFile)
2) write field description to <field>.txt   (CreateTextFile)
3) append field into spec using             (SpecFieldLogicAppender)  <-- replaces Method appender
4) generate field delegate via              (OpenAiFieldDelegateGenerator)
5) insert field using                       (ClassFieldCloner preferred) or ClassFieldAdder

Field requirements:
• NEW field logic must be natural language in < >
• One field = one pipeline
• Delegates must be regenerated every field addition
• **All generated fields in delegate are public — ALWAYS**
• Cloning is ALWAYS preferred over adding

FIELD BEFORE METHOD RULE:
• For every field <F> that will be used in a method, this pipeline
  MUST be completed (including clone/add into base) BEFORE any method
  pipeline describes logic that uses <F>.
• Never generate methods that rely on fields which do not yet exist
  in the current spec / base class.


────────────────────────────────────────
Rule 3.6 — UNIFIED DELEGATE PATH (MUST FOLLOW)
────────────────────────────────────────

Spec → Delegate → Clone/Add → Base

Always required for:
✔ new methods  (delegate from OpenAiMethodDelegateGenerator)
✔ new fields   (delegate from OpenAiFieldDelegateGenerator)
✔ mixed upgrades

Nothing may bypass delegate generation.

ORDERING INSIDE THIS PATH:
• For new fields:
    FIELD pipeline first → field delegate → clone/add to base.
• For methods that use those fields:
    Only after the field pipeline is complete, run the METHOD pipeline
    with a method delegate and clone/add methods.


Rule 4 — Editing existing methods:
Regenerate delegate + re-clone using ClassMethodCloner.

Rule 5 — Every new project starts:
CreateDirectory + CurrentDirUpdate


Rule 6 — DynamicClassCreator always generates:
• class with one default String field "name"
• one public method sayHello()


Rule 7 — Every instruction line MUST end with:
%%%)))


Rule 8 — Delegates ALWAYS named:
<ClassName>Delegate.java


Rule 9 — Dependency rule:
If A calls B → B must exist before A is inserted.

FIELD–METHOD DEPENDENCY EXTENSION:
• If a method <M> uses a field <F>, then <F> must already exist
  (created + cloned/added into the base and reflected in the latest spec)
  BEFORE the method pipeline for <M> is executed.


────────────────────────────────────────
Rule 10 — ANGLE BRACKET PROTOCOL
────────────────────────────────────────

10a — ALL identifiers must be <wrappedLikeThis>  
10b — A logic file contains ONE <description capsule> only  
10c — ASCII drawings must be described, not drawn  


Rule 11 — Required libs BEFORE cloning:

• net.bytebuddy:byte-buddy:1.15.3
• org.ow2.asm:asm:9.8
• org.ow2.asm:asm-tree:9.8


Rule 12 — (removed)

Rule 13 — Only main() may be static.

Rule 14 — After every clone/add → regenerate spec JSON.
